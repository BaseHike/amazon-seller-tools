# 第7步：诊断归类 → 广告动作 → 验证 → 输出

先按 `diagnosis-framework.md` 归类，再匹配动作，最后写报告。分点写清楚，先结论后数据。数字保留：金额 2 位小数、比率 1 位小数百分比。

## 4.1 归类

把六层结论对照框架的"四种诊断结果"：
- **A 市场生命周期**：第①层"市场降 + 竞品降 + 自己降"。
- **B 流量获取**：第②层"流量降、转化稳"。再按第③层分成"核心自然流量 ↓"或"广告流量 ↓"。
- **C 转化竞争力**：第②层"流量稳、转化降"，第⑤层找到输给竞品的项。双降时 C 排在前面。
- **D 流量结构**：只看两条——trend 的广告订单占比（月或周）上升且自然订单下降，或 trend 输出了 ⚠ 危险信号。广告订单占比没升、也没有危险信号，就**不归 D**。搜索词结构变化、匹配方式占比变化、高 ACOS 词属于第⑥层的广告问题，写进动作表，不能拿来判 D。

可以主次叠加（如"主 B，次 D"）。一个都不命中，就如实写"未发现明确的下滑原因"，不要硬套。

## 4.2 匹配动作

按框架的"诊断结果 → 广告动作 → 验证"表选动作，用第⑥层的 filter / 否词 / 广告位候选填具体对象和参数。
- **关键词机会**：读 `keyword_opportunities.md`，按 `keyword-opportunities.md` 6.6 的"诊断结果 → 用哪些来源"取舍。C 类只用 K1，K2–K4 在表里写"暂缓：等 CVR 回升"；A 类只用 K1，不新增测试词。自家品牌词单独一行（品牌防守），不算拓流量。
- 只给和诊断结果对得上的动作。filter 里的候选和诊断结果无关时不放进动作表（可以放进附录）。
- C 类先给价格 / 页面 / 产品这些**非广告动作**，广告动作只做"保高效、收低效"。
- A 类不建议加广告，动作以控成本、控库存为主。
- 用户的第一反应如果是误操作（销量掉就加预算、ACOS 高就降竞价、排名掉就加广告），在"不建议做的"里说明为什么。

## 4.4 规则
- 动作具体到"在哪个活动、对哪个词、做什么、调到多少"，每个动作都有验证指标。
- 数据不足的结论标"推测"。西柚数据标"估算"。
- **ACOS 要写来源**：整体 ACOS / TACOS 用 trend 的输出（daily.csv）；搜索词报告算出来的只能叫"搜索词 ACOS"，不能写成"整体 ACOS"。两个数不同很正常（归因口径不同）。
- 本 skill 只给建议，**不直接执行**否词、调价等写操作；用户明确要求执行时，逐项确认后再用领星 write 工具。
- 文件导出（筛选结果 Excel 等）给出路径。
- **两处都要有**：
  1. **对话里**：最后一条回复就是完整报告，按 4.3 模板从标题写到"六、需要你提供 / 确认"。不能只给摘要、只贴文件链接，也不能写"详见文件"。
  2. **文件里**：同样的内容写到 `<skill目录>/data/ad-data/<ASIN>_<日期>/report.md` 留档，对话末尾附一行文件路径。
  两边内容必须一致；对话里改了结论（比如用户回答了问题），要同步更新文件。
- 同一 ASIN 在 `<skill目录>/data/ad-data/` 下有更早的 report.md（旧版叫 `诊断报告.md`）时，先读它，填"与上次相比"那一行；上次的复查计划到期了，就对照它的验证指标说明有没有达到。
- 报告出完后检查要不要写回记忆：新确认的竞品、核心词、阶段或目标 ACOS 变化，问用户一句后写进 asin-profiles.md，并更新"更新于"。
