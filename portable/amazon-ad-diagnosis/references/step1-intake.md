# 第1步：收集信息 + 拉数据

> **通用版提示**：本文件和 Claude 版共用。文中的“子代理 / 主代理”都由你自己按顺序做；AskUserQuestion、ToolSearch、Agent 工具、`claude mcp add` 等说法，按 `references/portable-runtime.md` 换成你所在软件的做法。

## 1.0 先查 ASIN 记忆（每次都做，在问其他问题之前）

用过的 ASIN 资料（售价、采购、头程、FBA、佣金、毛利率、目标 ACOS、阶段、店铺、竞品）记在 **skill 自己的 `data/asin-profiles.md`** 里，跟着 skill 文件夹走，不放到别的地方，也不用环境变量。格式、计算公式和修改规则写在 `references/asin-profiles.md`（模板）开头，**由 AI 直接读、直接改**。

- 资料文件：`<skill目录>/data/asin-profiles.md`（`<skill目录>` = 本 skill 加载时的 Base directory，也就是 SKILL.md 所在的文件夹）。
- **不存在时**（第一次用）：把 `<skill目录>/references/asin-profiles.md` 复制成 `<skill目录>/data/asin-profiles.md`，再往里加记录。
- 真实记录**只写进 `data/` 这份**，不要写进 `references/` 的模板，也不要写到工作目录、用户目录等其他地方。`data/` 已被 git 忽略，不会提交到 GitHub。

1. 读 `<skill目录>/data/asin-profiles.md`，列出已记录的 ASIN。
2. **每次都先问这次分析哪个 ASIN**（即使用户消息里已经写了 ASIN，也要在这一步确认）：
   - 有记录的：用 AskUserQuestion，选项是已记录的 ASIN（按"更新于"从新到旧，最多 3 个；标签写"ASIN 名称/规格"，说明里写站点、盈亏平衡 ACOS、目标 ACOS），再加一个"**新增 ASIN**"；其他已记录的，用户可以从 Other 输入。用户消息里提到的那个 ASIN 放第一个。
   - 一个都没有：直接问 ASIN 和站点，并说明"这是第一次，资料会记下来，以后直接选"。
   - 选了"新增 ASIN"或者给了一个没记录过的：按模板问齐资料，加进文件末尾（见第 3、4 条）。
3. **在文件里找这个 ASIN（同站点）——先查完，再问其他问题**：
   - **找到了** → 记下那一节，以及标了"待确认"的项，放到第 4 条一起问。
   - **没找到** → 是新 ASIN，模板里要填的项放到第 4 条一起问。
4. **其余问题合并成一次提问**，不要一项一项来回问：
   - 找到了：把那一节列给用户，问"这些还对吗？有变化直接告诉我"，并问清"待确认"的项；
   - 没找到：告诉用户"这个 ASIN 还没记录过，先把资料补上，以后就不用再问了"，列出模板里要填的项；
   - 再加上 1.1 里记忆没有的项、截止日期、近期改动；记忆里没有竞品时顺便问一句主要竞品 ASIN（不知道可以不填）；没有"品牌词（自家）"时顺便问自家品牌名和常见拼法（第 6 步区分品牌词用）。
   选择题（阶段、截止日期用默认昨天还是别的、近期改动）放进同一次 AskUserQuestion（最多 4 题）。近期改动用多选，选项至少分开列：广告、Listing、价格、**优惠促销（优惠券 / 订购省 / Deal / Prime 折扣）**、都没改；要填数字的（成本、目标 ACOS）在同一条消息里用文字列出来一起问。
   用户回答后：改了哪项就改文件里哪项；新 ASIN 算出毛利率和盈亏平衡 ACOS，在文件末尾加一节，再把算出的结果给用户确认。
5. 分析过程中用户补充或更正了资料（比如归因时给了竞品 ASIN、改了目标 ACOS），随时改文件。
6. 目标 ACOS 高于盈亏平衡 ACOS 时，要提醒用户。

## 1.1 必问清单

用 AskUserQuestion 或直接提问。用户已经说过的、记忆里已有并且用户确认没变的，都不要再问。

| 信息 | 用途 | 没给怎么办 |
|---|---|---|
| ASIN（说明是父体还是子体）、站点（US/UK/DE…） | 拉数据的主键 | 必须问，没有不能继续 |
| 领星里的店铺名（同站点多店铺时） | 确定 sid | 子代理列出店铺后让用户选 |
| 产品阶段：新品 / 成长 / 稳定 / 利润 / 清库存 | 决定"好坏标准" | 必须问 |
| 目标 ACOS（或目标 TACOS） | 判断超标 | 可由成本推算后让用户确认 |
| 售价、采购成本、头程、FBA 费、佣金比例（或直接给毛利率） | 算盈亏平衡 ACOS | 先查记忆（1.0）；只缺一部分时可用领星利润报表补，仍缺就问；问到后写进 asin-profiles.md |
| 主要竞品 ASIN（可选） | 第①⑤层要和竞品比 | 先查记忆；用户不知道就不问，派外部子代理前主代理用西柚找 |
| 分析截止日期 | 日/周/月的锚点 | 默认**站点当地时间**的昨天（今天数据不完整；美国站按美西时间，常比北京时间晚一天），告诉用户 |
| 近 30 天是否改过：广告结构/竞价/预算、Listing、价格、优惠促销（优惠券、订购省、Deal、Prime 折扣，要单独列出来问） | 区分人为变化与自然波动 | 必须问；子代理也会拉广告操作日志交叉核对；价格和优惠在第④⑤层（内部归因）会用西柚价格趋势再核对 |

盈亏平衡 ACOS = 毛利率 =（售价 − 采购 − 头程 − FBA − 售价 × 佣金比例 − 其他）÷ 售价（和 asin-profiles.md 用同一个公式）。

阶段对应的常见 ACOS 容忍度（只作参考，以用户给的为准）：新品 40–60%+；成长期 ≈ 盈亏平衡；稳定期略低于盈亏平衡，以守住排名为主；利润期低于盈亏平衡，常见 15–30%；清库存视清仓价。

### 1.1.1 核对用户自述（数据回来后马上做，第 2 步之前）

用户说的情况是**待核实的假设**，不是事实。数据拉回来后逐项核对，对不上就追问：

| 用户说法 | 怎么核对 | 对不上时 |
|---|---|---|
| 只投了某个规格 / 某几个 ASIN | `variant_ads.csv` 里有其他 ASIN 的花费；或者 `campaigns_daily.csv` 近 7 天花费合计比 `daily.csv` 同期 spend 高出 5% 以上 | 列出其他 ASIN 的花费和 ACOS，问是不是有意投放、要不要算进来 |
| 预算是多少 | 活动每日预算求和，再看近 7 天实际日均花费 | 告诉用户实际数字，问以哪个为准 |
| 最近改过什么 | 跑 `ad_diag.py oplog --file op_log.csv`，按日期看手动做的暂停、预算、竞价、溢价变更（见 ads-diagnosis.md 6.2） | 列出日志里有、但用户没提的大操作 |
| 关停了 ASIN 定投 / 某些活动 | 先用 `oplog` 找到暂停日期，再跑 `ad_diag.py structure --file campaigns_daily.csv --change-date <暂停日期>`：看"ASIN定投"花费占比的变化和"改动后不再花费的活动"名单。比例 = 1 − 改动后 ASIN 定投花费 ÷ 改动前 | 把名单和占比变化贴进核对表；**暂停了几个活动以 oplog 为准**（"不再花费"不等于都是那天暂停的）；停得比说的多或少都要问 |
| 把某些词改成广泛 / 精准 / 词组 | 用 `oplog` 找改动日期（找不到就用同一批调整里能找到的日期，比如暂停定投那天，并注明"日期按 X 推定"），跑 `ad_diag.py structure --file campaigns_daily.csv --change-date <日期>`，**只按 structure 输出的"[改成广泛]"等行的占比方向下结论**。跑了多个日期、结果不一致时，**以用户说的那批调整的日期（或推定日期）那一次为准**，其他日期只作补充证据，不改变结论。这里**不用 terms**：terms 只比最近两周，验证不了更早的改动，而且按 SOP 第⑥层最后才跑 | 占比方向和用户说的相反才算"不一致"，直接指出，问指的是哪个活动；数据覆盖不到改动日期时写"无法核对" |
| 预算降到 N 以下 | daily.csv 近 7 天日均 spend；`oplog` 里的预算变更 | 告诉用户实际数字 |
| 阶段 vs 目标 ACOS | 目标 ACOS 高于盈亏平衡，但阶段说是"利润期"或"稳定期" | 指出矛盾，确认以哪个为准 |

核对结果写成一张表，后面原样放进报告第二部分（见 output-format 4.3）。每条用户说法都要有一行，不能用"基本一致"一句带过：

| 用户说法 | 数据证据（文件 + 数值 / 活动名单 + 日期） | 结论：一致 / 不一致 / 无法核对 |
|---|---|---|

暂停、开启的活动要直接引用 `oplog` 输出的活动名单。

输出一行确认后再往下走：
> 判断标准：ASIN=X，站点=Y，阶段=Z，目标 ACOS=A%（盈亏平衡 B%），截止日期=D

## 1.2 找数据 MCP（领星 ERP + 西柚）

先**宽泛地找**；确实找不到，再问用户怎么配置（1.2.1）。服务 ID 每台机器不同，工具名也会随版本变，**不要因为某一个 toolId 搜不到就判定不可用**。

**领星 ERP**（工具名形如 `mcp__<服务ID>__help` / `__search` / `__action`）：
1. ToolSearch 依次搜 `help search action`、`领星`、`lingxing`、`广告 店铺`，找以 `__help` 结尾的工具；找到就用 select: 一次加载同一服务的 help / search / action。
2. 调 help，query 用中文关键词（"广告活动""店铺""产品表现"），一个搜不到换下一个，也可以不带 query 分页看全部。返回了亚马逊店铺、广告、销量这类工具（如 toolId 以 `ad_`、`get_my_sids`、`query_product_` 开头，或 displayName 里有"广告""店铺"），就算可用。
3. 有多个疑似服务时都试一下 help，选能返回亚马逊广告工具的那个。

**西柚**（找词、ABA、类目和竞品数据，工具名形如 `mcp__<服务ID>__get_asin_keywords`）：
1. ToolSearch 依次搜 `get_asin_keywords get_keyword_info`、`西柚`、`xiyou`、`keyword aba category`，找关键词 / ABA / 类目市场类工具。
2. 找到后，有 `get_account_credit_quota` 就调一次，记下剩余额度（外部、内部归因要控制用量）。西柚每次调用都要填 user_task（用户原话）和 intent_summary。

查完用一句话告诉用户：领星 可用/不可用；西柚 可用/不可用（剩余额度 N）。

### 1.2.1 找不到时：问用户怎么配置

**先排除"配了但没连上"**：有命令行时执行 `claude mcp list`，看有没有名字像领星 / 西柚的服务（lingxing、xiyou 等）。状态是需要登录或连接失败的 → 告诉用户是哪一个，请用户重新登录或在连接器设置里重新连接，不要重复添加。

确实没有时，用 AskUserQuestion 问（领星、西柚都缺就各问一题，选项相同）：
- **帮我配置（推荐）**：AI 按当前软件的步骤加到**全局**，所有项目、所有会话都能用
- **我自己配置**：AI 给出步骤，用户配好后告诉 AI
- **先不配置**：领星用现成数据或手动导出的报表；西柚改用浏览器 / 网页搜索（第①④层可信度会降低）

**帮我配置**：
1. **问 MCP 地址和授权方式**（同一条消息里说明去哪拿）：领星在 ERP 后台的开放平台 / AI 助手设置里；西柚在西柚开放平台。授权方式是"浏览器登录授权"还是"给了一个令牌"。
2. **按当前软件加到全局**。判断方法：你能执行 Bash / PowerShell 命令 → 走 Claude Code 方式；不能执行命令 → 走连接器设置。
   - **Claude Code**（命令行、IDE 插件、桌面应用的 Code 标签页）：授权方式是浏览器登录或不需要授权时，用 Bash / PowerShell 执行下面的命令（西柚把名字换成 `xiyou`）；授权方式是令牌时，**AI 不执行任何添加命令**，直接到第 3 步。`--scope user` 就是全局；不加的话只对当前项目生效。找不到 `claude` 命令时，Windows 试 `%USERPROFILE%\.local\bin\claude.exe`。
     ```bash
     claude mcp add --scope user --transport http lingxing "<MCP地址>"
     ```
   - **Claude 网页版 / 桌面应用的聊天界面**（没有命令行）：全局配置在"设置 → 连接器（Connectors）→ 添加自定义连接器"，填名称和 MCP 地址。这是用户账号里的设置：告诉用户点哪里、填什么，由用户自己点保存。
3. **授权**：
   - 浏览器登录授权：新开会话后第一次用到时按提示登录；命令行里也可以在会话中输入 `/mcp`，选这个服务登录。
   - 令牌：**AI 不填写、不经手令牌，也不先加一个不带令牌的版本**。把下面这条命令给用户（地址替换成用户给的），请用户把令牌换进去后自己在终端执行，令牌不要发给 AI。连接器设置方式下，告诉用户在添加连接器的页面里自己填令牌。
     ```bash
     claude mcp add --scope user --transport http lingxing "<MCP地址>" --header "Authorization: <你的令牌>"
     ```
4. **检查**：执行 `claude mcp list`，能看到 lingxing / xiyou，状态是已连接或需要登录，就算加好了。不要用 `claude mcp get`，它可能把令牌打印出来。
   `claude mcp list` 里状态是连接失败 → 请用户核对地址和令牌（AI 不看令牌），改好后再查一次；还是失败，就再问一次：重新配置，还是先不配置。
5. **告诉用户**：已经加到全局；当前会话不会自动加载新工具，要**新开一个会话**再发起分析。领星没配好 → 这次停在这里，或用户改选"先不配置"；只缺西柚 → 可以先按"先不配置"继续。

**我自己配置**：不用先问地址。按用户当前的软件，把上面第 2、3 步写给用户（用户已经给了地址就直接填进去，令牌始终用占位符），说明加 `--scope user` 才是全局，配好后新开会话。领星没配好前停在这里；只缺西柚可以先继续。

**先不配置**：
- 领星：按顺序找数据。
  1. `<skill目录>/data/ad-data/<ASIN>_*/` 里有没有 daily.csv、st_curr.csv 等文件，再看用户这次上传的文件。（旧版把数据放在当前工作目录的 `<skill目录>/data/ad-data/` 下；发现旧数据时告诉用户，问要不要搬进 `<skill目录>/data/ad-data/`。）有就直接用，告诉用户用的是哪个目录、数据截止到哪天。
  2. 也可以用浏览器打开领星网页或卖家后台导出报表，或读本机其他目录里的报表。用浏览器或打开其他目录前，先跟用户说一声要去哪里找。
  3. 都没有 → 请用户从卖家后台 / 领星手动导出：广告活动日报（近 60 天）、业务报告按日期（近 60 天，含 Sessions）、搜索词报告（近 7 天 + 前 7 天）。
- 西柚：外部子代理改用浏览器看亚马逊前台、网页搜索补市场和竞品数据（见 step3 3.2，可信度最高"中"）。

任何情况下都**不要替用户填写令牌或密码**。

## 1.3 派子代理拉数据

用 Agent 工具，`subagent_type: "general-purpose"`，`description: "拉取领星广告数据"`。prompt 取 `lingxing-data-pull.md` 中"子代理 Prompt 模板"整段，把 `{{...}}` 替换成实际值。

主代理只接收子代理返回的：文件路径列表 + 每个文件行数 + 缺失项说明。不要让子代理把原始数据贴回来。

子代理返回后检查：
- `daily.csv` 至少覆盖 60 天（月环比需要，模板拉 62 天）；不足时告诉用户月对比不可用或只能部分对比。
- 截止日的 sessions / 总订单为空（领星没回传）：**看 trend 脚本的提示决定挪不挪**。daily.csv 覆盖到截止日往前 61 天以上时，才把 `--date` 往前挪一天，并告诉用户实际用的截止日；只有 60 天时**不要挪**（挪了月环比就算不出来），保持原截止日，报告注明当天哪些字段缺失。数据文件夹**不改名**，报告、归因结果都继续放在这个文件夹。
- 缺失项（如没有 SQP 自然曝光）记下来，trend 里对应指标会显示"缺数据"，报告照写。
