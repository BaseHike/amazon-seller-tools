# 亚马逊销售下滑 / 广告诊断（通用版：Codex、WorkBuddy 等）

> 这是通用版，给没有 Claude 子代理工具的 agent 用。references 里写给"子代理""主代理"的步骤，**都由你自己按顺序做**；遇到 AskUserQuestion、ToolSearch、Agent 工具、`claude mcp add` 等 Claude 专用说法，先读 `references/portable-runtime.md` 换成你这里的做法。

**判断标准在 `references/diagnosis-framework.md`**：
- 不是哪个指标差就改哪个，而是找到**第一个发生异常的变量**。
- 订单 = 流量 × CVR。
- 先分清是市场的问题还是链接自身的问题。
- **广告最后才诊断**，广告动作只解决已经诊断清楚的问题。
- 不要建议"销量掉就加预算、ACOS 高就降竞价、排名掉就加广告"。

七步，严格按顺序；每步有结论再进下一步（第2–5步就是 SOP 的 ①→⑥：外部先、广告最后；第6步关键词机会；第7步归类和输出）。**进入某一步时再读对应的 references 文件**，不要一次全读。

## 第 0 步（必做）

1. **读 `references/portable-runtime.md`**。里面写了 Claude 专用说法怎么换，也列了弱模型最常犯的错。
2. **读用户资料文件** `<skill目录>/data/asin-profiles.md`（用 python 以 utf-8 读）。
   - 不存在时（第一次用），把 `<skill目录>/references/asin-profiles.md`（模板）复制成 `<skill目录>/data/asin-profiles.md`。
   - 资料**只**读写这一个文件。**不要**用 rg、find 或递归搜索去别的目录找，也不要写到其他地方、不要设环境变量。

## 开始前必须知道的三件事

1. **skill 目录** = 本 SKILL.md 所在的文件夹。先用 shell 确认它的绝对路径（references 里的 `<skill目录>`、`${CLAUDE_SKILL_DIR}`、Base directory 都指它）。
   - 脚本：`python "<skill目录>/scripts/ad_diag.py"`。子命令有六个：`trend` 多周期对比、分层判定、找第一个异常变量；`terms` 词结构对比；`filter` 组合筛选；`harvest` 关键词收割候选；`oplog` 操作日志按日期汇总；`structure` 改动前后的活动类型花费占比。
   - **python 命令**：指 Python 3（3.9 以上）。Mac / Linux 上没有 `python` 时用 `python3`，先跑一次 `python --version`（或 `python3 --version`）确认；报 `No module named pandas` 时，告诉用户按 `<skill目录>/scripts/requirements.txt` 安装（`python -m pip install -r …`），用户同意后再装。
2. **数据文件**是 UTF-8 带 BOM 的 CSV。读写都用 python，`encoding="utf-8-sig"`；在 Windows 上打印中文前先 `sys.stdout.reconfigure(encoding="utf-8")`。不要用 PowerShell 的 Get-Content 读，中文会乱码。
   - 所有数据放在 **`<skill目录>/data/ad-data/<ASIN>_<截止日>/`**（和资料文件一起在 skill 的 `data/` 里，跟着 skill 走）。不要放到当前工作目录或其他地方。
   - 报告和归因结果也放这里。
3. **只读不写**：领星、西柚、浏览器都可以用，但**不执行**任何会改动广告或 Listing 的操作（否词、调价、改预算、开关活动、改 Listing），只写成建议。西柚按次扣 credits，单次几百 credits 的报告类工具要先问用户。
   - 找数据只用 MCP、工作目录里的文件、用户上传的文件。
   - 要用浏览器、读其他目录前，先告诉用户要去哪里。
   - **不要**列桌面窗口、操作其他应用。

**写入 `data/` 失败时**（报 "writing outside of the project"、权限不足、sandbox 拒绝等）：**立刻停下**，告诉用户报错原文，以及怎么让这个目录可写（见 `references/portable-runtime.md`"让 data/ 可写"）。**不要**改写到工作区或其他目录，**不要**跳过 terms / filter，也**不要**自己用 python 重新算一遍代替脚本。

**要问用户时**：把问题编号，一次列完，选择题写出选项，然后**停下来等用户回答**，不要自己假设答案往下做。

**说某个文件"缺失"之前先检查**：开始分析时，先列出数据目录的文件清单，PowerShell 用 `Get-ChildItem <skill目录>/data/ad-data/<ASIN>_<日期>`，并把清单写进 `rootcause_internal.md` 开头。报告里要说某个文件或字段缺失，必须先用 `Test-Path` 或 python 确认过；清单里有的文件**不能**写成缺失，也不能让用户再提供。字段缺失要写到具体是哪个字段、哪几天，例如"11/15 的 sessions"，不要笼统地说"数据缺失"。

**第一轮回复只做提问**：即使 `<skill目录>/data/ad-data/` 里已经有数据，第一轮也只做两件事——读资料文件、合并提一次问。要问的内容：
- **第一条：这次分析哪个 ASIN**。把资料文件里已记录的 ASIN 列成编号选项（用户消息里提到的排第一，写出名称 / 站点 / 目标 ACOS），最后一个选项固定是"新增 ASIN"。只有一个记录也要这样列；
- 把选中 ASIN 的资料列出来，请用户确认；
- 截止日期；
- 近期改动，优惠券和订购省要单独问；
- 资料里缺的项。

问完就结束这一轮。用户回答之前，**不要**跑 trend，**不要**写 report.md。

## 第1步：收集信息 + 拉数据
读 `references/step1-intake.md`

1. **先查 ASIN 记忆**：
   - 读 `<skill目录>/data/asin-profiles.md`，列出已记录的 ASIN。
   - **每次都问这次分析哪个 ASIN**（即使用户消息里写了 ASIN 也要确认）：已记录的列成选项（用户提到的放第一个），最后加一个"新增 ASIN"。
   - 有记录：列出来，请用户确认有没有变化。
   - 没有记录：问齐资料，加进这个文件。
   - 详见 intake 1.0。
2. **把记忆里没有的项一次问清**：
   - ASIN（父体还是子体）、站点、店铺
   - 产品阶段与目标 ACOS
   - 成本（用来算盈亏平衡 ACOS）
   - 主要竞品 ASIN（可选）
   - 分析截止日期
   - 近期是否改过广告、Listing、价格、优惠促销。优惠券、订购省、Deal 要单独问，用户容易漏。
3. **找领星 ERP 和西柚 MCP**：
   - 在你的工具列表里按名字找。领星有 help、search、action 三个工具；西柚有 get_asin_keywords、get_keyword_aba_trends 等。
   - 找不到时，按 `references/portable-runtime.md` 的"配置 MCP"告诉用户怎么在当前软件里配置。令牌让用户自己填。
   - 也可以先用 `<skill目录>/data/ad-data/` 里的现成数据，或用户导出的报表。
   - 领星既没配好、也没有现成数据时，停在这里。
4. **你自己拉数据**：按 `references/lingxing-data-pull.md` 的模板，把模板里写给子代理的要求当成写给你的。
   - **按日期分段拉**，每次只拉一小段。
   - 原始返回存成文件，用 python 解析成 CSV，不要把大段 JSON 留在对话里。
5. **核对用户自述**：数据回来后，按 intake 1.1.1 逐行核对：
   - 投放规格、预算、阶段与目标 ACOS；
   - 近期调整：先跑 `ad_diag.py oplog --file <skill目录>/data/ad-data/<ASIN>_<日期>/op_log.csv`，看手动做过的暂停、预算、竞价、溢价变更。不要自己用 python 打印 op_log，中文容易乱码。
   - 用户说"改成广泛 / 关了定投"：用 oplog 找到改动日期，再跑 `ad_diag.py structure --file <skill目录>/data/ad-data/<ASIN>_<日期>/campaigns_daily.csv --change-date <改动日期>`，按它输出的类型占比变化和"停掉"名单下结论。**方向相反就直接指出**，不要写成"已确认"。

   对不上的先问用户，再进第 2 步。

## 执行顺序 = SOP 顺序

按诊断框架 ① → ⑥ **依次下结论**：先外部（市场），再链接自身（②③ → ④⑤），**广告最后**。每层结论写进文件后再进下一层。第⑥层的 terms / filter **等 ④⑤ 写完才跑**——脚本会检查：数据目录里没有 `rootcause_external.md` 和 `rootcause_internal.md` 时，terms / filter / harvest 直接拒绝运行（⛔）。

**一步一层**：每一步只跑这一层要用的命令，写完这一层的文件，再进下一步。不要一次把所有脚本跑完再补写结论。第 3 步写 ②③ 结论前，先确认 `rootcause_external.md` 已经存在。

## 第2步：准备 + 第①层 市场需求（外部，先做）
读 `references/diagnosis-framework.md`（判断标准）、`references/step2-compare.md` 2.6、`references/root-cause-agents.md` 的外部模板、`references/step3-root-cause.md` 3.1–3.2

1. 跑 `ad_diag.py trend --file <skill目录>/data/ad-data/<ASIN>_<日期>/daily.csv`。**这一步只看最后一段"第①层 市场需求（外部）输入"**：自身变化率 S、**主周期**、**异常起点**和起点前后对比窗口。②③ 的结论先不写。
2. 准备核心词（资料里的；没有就用 `st_curr.csv` 花费 / 订单前 5）和竞品 ASIN（资料里的；没有就按 root-cause-agents.md"找竞品"）。
3. 按外部模板做：**先比起点前后两个窗口**的市场和竞品，**再按主周期**做日历周期对比，结论以主周期为准 → 写 `rootcause_external.md`（市场对照表第一行"起点前后"，主周期那行标 ★）。
4. 拿不到西柚数据也要写这个文件：市场列填"缺数据 / 无法判定"，写出要问用户的市场问题，例如"最近一个月你看到核心词搜索量、竞品价格或 Deal 有没有明显变化？"。

## 第3步：第②③层 销售拆解（链接自身）
读 `references/step2-compare.md`

1. **分周期看环比（step2-compare 2.3a）**：用第 2 步 trend 的输出，按 **日 → 周 → 月 → 年** 的顺序，每个周期单独写一句结论。"年"这句分两半写：① 去年同期月环比（季节性）；② 年同比（整体水平比去年高还是低）。判定**以脚本输出原文为准**，例如持续上升、持续下降、周升月降、近一周上升、月度下降、单日波动、持平。**不能只看本周。**
2. **跨周期对比（2.3b）**：trend 的"跨周期一致性"表**整张照抄进报告**（所有行都要有，差异解读一字不改，自己的补充写在表下面）。总订单那一行的解读作为这一步的主结论（今年真的变差 / 偏季节性 / 近期才开始 / 单日波动…；季节性看"今年月环比 vs 去年同期月环比"，不看年同比）；再写其他指标和它一致还是矛盾，矛盾的地方写进异常点。没有去年数据时写"缺年同比"。表下必须写一句**"偏季节性的指标：…；今年真的变差的指标：…"**，一句话结论和第 7 步的主诊断都要用这个区分（例如"Sessions、自然订单的下滑偏季节性，去年同期也跌了约 34%；广告订单、点击是今年真的变差"），不能把季节性的下滑也算到今年的操作上。
3. **第②层**：脚本给出"流量降 / 转化降 / 双降 / 都没降"，这决定第 4 步先查 ④ 还是 ⑤。
4. **第③层**：脚本给出掉的是自然流量还是广告流量。广告流量先掉时，到 oplog 找起点附近的广告操作——这是第③层的判断，不是第⑥层。
5. **第一个异常的变量**和 **⚠ 危险信号**（广告单稳、自然单降、广告占比升）记下来，第 7 步判 D 时要用。

## 第4步：第④⑤层 关键词权重 + 相对竞争力（内部）
读 `references/root-cause-agents.md` 的内部模板、`references/step3-root-cause.md` 3.3–3.5

1. 带上第①②③层结论，按内部模板做：流量降重点查 ④，转化降重点查 ⑤，双降两个都查、⑤ 优先 → 写 `rootcause_internal.md`。
2. 没有 MCP 也要写：用 daily.csv 的价格、评分、库存写 Listing 因素；用 st_curr.csv / st_prev.csv 里核心词的点击、订单写第④层；竞品对比拿不到的写"缺数据"和要问的问题。

## 第5步：第⑥层 广告诊断（最后才做）
**先读完 `references/ads-diagnosis.md`，再跑 terms / filter**（四个结构、否词关联性检查、调价规则都在里面）

1. 跑 `ad_diag.py terms`。词结构有变化时，先核对操作日志。看到 ⛔ 说明前面的层没写完，回去补，不要加 `--force` 绕过。
2. 跑 `ad_diag.py filter`。`--target-acos` 用 asin-profiles.md 里的目标 ACOS，**不要用示例值**。
3. 看广告位。这一层只记录问题，**不改变 ①–⑤ 的结论**，不在这里定动作。
4. 这一层要问用户的问题先记下，到第 6 步末尾合并一次问。

## 第6步：关键词机会（第⑥层之后，列候选）
读 `references/keyword-opportunities.md`

前五步找"为什么掉"，这一步找"**还有哪些词值得投**"。这一步只列候选，第 7 步再按诊断结果取舍。

1. **K1 收割词（必做）**：跑 `ad_diag.py harvest --curr st_curr.csv --prev st_prev.csv --target-acos <资料里的目标ACOS> --brand <自家品牌词>`。它列出已出单、ACOS 达标、还没单独开精准的搜索词，带建议精准竞价和要加精准否定的来源活动。**不要用示例值**。
2. **K2 冲刺词 / K3 竞品缺口词 / K4 市场词**（西柚）：按 ①–⑤ 的结论定先查哪个。流量问题先查 K2、K3；转化问题可以不查 K2–K4（第 7 步也会暂缓）。西柚这一步总共不超过 5 次调用；没有西柚时只做 K1，写明"K2–K4 缺西柚数据"。
3. K2–K4 的候选按顺序过三关：**相关性 → 去重 → 可承受 CPC**（客单价 × 预估 CVR × 目标 ACOS）。结果写进 `keyword_opportunities.md`。
4. **合并提问**：①–⑥ 各层和这一步要问的问题合并去重，**一次问用户**，等回答后再进第 7 步。拿不到的数据要**明确列出**，不要编。

**进第 7 步前检查**：数据目录里必须有 `rootcause_external.md`、`rootcause_internal.md`、`keyword_opportunities.md`，以及 trend、terms、filter、harvest、oplog 的结论。缺哪个就先补上。

做完每一项，就把结论写进对应的文件。上下文不够时，后面的步骤读文件，不要靠记忆。

## 第7步：诊断归类 → 广告动作 → 验证 → 输出
读 `references/output-format.md`

1. **按 ①→⑥ 写诊断路径**：每层一句结论，标出第一个异常的变量；市场对照表**主周期那一行加粗**，第①层结论按主周期写。
2. **归为四种诊断结果**（见 `diagnosis-framework.md`）：A 市场生命周期、B 流量获取、C 转化竞争力、D 流量结构。可以主次叠加；都不命中就如实写"未发现明确的下滑原因"。 **偏季节性的指标不能算作某次操作或某个原因的结果**：跨周期表里判为"偏季节性"的指标（如 Sessions），在一句话结论和诊断结果里要写成"和去年同期一致（偏季节性）"，只有超出季节性的部分（"今年真的变差"的指标）才归到具体原因。写法示例："Sessions −34% 和去年同期一致（偏季节性）；今年额外的下滑来自广告订单、点击（比去年同期多降 xx pp），对应 10/18 关停定投"。
   - **D 的硬条件**：trend 显示广告订单占比上升**且**自然订单下降，或者 trend 输出了 ⚠ 危险信号。两条都不满足时，诊断结果里**不能出现 D**，主、次都不行。搜索词结构变化、高 ACOS 词都算第⑥层的广告问题，写进动作表就行。
3. **按诊断结果匹配广告动作**：每个动作写清对象、参数、验证指标、复查日期；否词清单单独列。**关键词机会**按 `keyword-opportunities.md` 6.6 的"诊断结果 → 用哪些来源"取舍（C 类只用 K1，K2–K4 写"暂缓"），写进报告的"关键词机会"表，每个新词都带止损规则。
4. **输出 + 存报告**：
   - 先写 `<skill目录>/data/ad-data/<ASIN>_<日期>/report.md`，然后**读出它的全文，最后一条回复就是 report.md 的逐字内容**：从标题到"六、需要你提供 / 确认"，只允许在末尾加一行文件路径；**不得删列、删段、合并或改写**，报告再长也不能压缩。
   - 以后每次更新 report.md，都重复一遍"读出全文、原样回复"，保证对话和文件一致。
   - 有上一次的报告时，加一行"与上次相比"。
   - 发出前自查：回复里必须有**跨周期表**和**用户说法核对表**，长度和 report.md 相当；少了任何一节、或明显比文件短，说明被压缩了，整段重贴 report.md 原文。
5. **写回记忆**：本次确认的新竞品、核心词、阶段或目标 ACOS 变化，问用户一句后写进 asin-profiles.md。
