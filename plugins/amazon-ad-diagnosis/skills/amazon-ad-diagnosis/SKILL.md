# 亚马逊销售下滑 / 广告诊断

**判断标准在 `references/diagnosis-framework.md`**：不是哪个指标差就改哪个，而是找到**第一个发生异常的变量**；订单 = 流量 × CVR；先分清市场还是链接自身；**广告最后才诊断**，广告动作只解决已经诊断清楚的问题。不要建议"销量掉就加预算、ACOS 高就降竞价、排名掉就加广告"。

七步，严格按顺序；每步有结论再进下一步（第2–5步就是 SOP 的 ①→⑥，第6步关键词机会，第7步归类和输出）。细节都在 `references/`，**进入某一步时再读对应文件**，不要一次全读。

脚本：`python "${CLAUDE_SKILL_DIR}/scripts/ad_diag.py"`（插件安装后 skill 不在当前项目里，必须用这个绝对路径调用；如果路径里还留着没被替换的 `$` 开头的变量名，就换成本 skill 加载时给出的 Base directory。references 里的 `<skill目录>` 指同一个目录）（`trend` 多周期对比 + 分层判定 + 第一个异常变量 / `terms` 词结构对比 / `filter` 组合筛选 / `harvest` 关键词收割候选 / `oplog` 操作日志按日期汇总 / `structure` 改动前后活动类型花费占比）。数据文件是 UTF-8 带 BOM 的 CSV，读写都用 python（encoding="utf-8-sig"），不要用 PowerShell 的 Get-Content 读（中文会乱码）。所有数据文件放在 **`<skill目录>/data/ad-data/<ASIN>_<日期>/`**（和 ASIN 资料一起放在 skill 自己的 `data/` 里，跟着 skill 走，git 会忽略；不要放到当前工作目录或其他地方；`<日期>` 是拉数据时定的截止日，之后即使把 `--date` 往前挪了也不改文件夹名，报告和归因结果都放这里，报告里写实际用的截止日）。

**python 命令**：指 Python 3（3.9 以上）。Mac / Linux 上没有 `python` 时用 `python3`，先跑一次 `python --version`（或 `python3 --version`）确认；报 `No module named pandas` 时，告诉用户按 `<skill目录>/scripts/requirements.txt` 安装（`python -m pip install -r …`），用户同意后再装。

工具不限：领星、西柚等 MCP，python，浏览器（看亚马逊前台、卖家后台、领星网页），网页搜索，读本机文件，都可以按需调用。西柚按次扣 credits，单次几百 credits 的报告类工具要先问用户。唯一不做的是**会改动广告或 Listing 的写操作**（否词、调价、改预算、开关活动、改 Listing）：只写成建议，用户逐项确认后才执行。

当前软件没有 Agent（子代理）工具时，主代理按同一个模板自己做：第1步自己拉数据；第3步依次做外部、内部，再做第⑥层和关键词机会。没有 AskUserQuestion 时，用一条文字消息把要问的问题列出来，等用户回答再继续，不要自己假设答案。

## 第1步：收集信息 + 拉数据
读 `references/step1-intake.md`

1. **先查 ASIN 记忆**：读 `<skill目录>/data/asin-profiles.md`（私有资料，跟着 skill 走，不存在就从 `references/asin-profiles.md` 模板复制一份）→ **每次都问这次分析哪个 ASIN**（已记录的做选项，加一个"新增 ASIN"；用户消息里提到的放第一个）→ 有记录就列出来让用户确认有没有变；新增的就问齐资料，加到文件末尾。资料只写这一个文件。详见 intake 1.0。
2. **向用户问清**记忆里没有的（缺一项都要问，不要假设；确认记忆和这些问题**合并成一次提问**，见 intake 1.0）：ASIN（父/子）、站点、店铺、产品阶段与目标 ACOS、成本（→ 盈亏平衡 ACOS）、主要竞品 ASIN（可选）、分析截止日期、近期是否改过广告/Listing/价格/优惠促销（优惠券、订购省、Deal 要单独问，用户容易漏）。
3. **宽泛地找领星 ERP 和西柚 MCP**（按关键词找，不靠某个固定的 toolId，见 intake 1.2）。确实找不到 → 问用户：**帮我配置**（AI 按当前软件的步骤加到全局，令牌由用户自己填）/ **我自己配置** / **先不配置**（领星用现成数据或导出的报表，西柚改用浏览器），见 intake 1.2.1。新配置的 MCP 要新开会话才生效；领星既没配好、也没有现成数据时，停在这里。
4. **派子代理拉数据**：用 Agent 工具（general-purpose），prompt 用 `references/lingxing-data-pull.md` 的模板填参数。子代理只把数据写成 CSV 并回传文件路径 + 一句摘要，原始 JSON 不进主上下文。
5. **核对用户自述**：数据回来后，按 intake 文件 1.1.1 核对投放规格、预算、近期调整（先跑 `ad_diag.py oplog` 看手动做过的暂停/预算/竞价/溢价；"关定投 / 改匹配方式"再跑 `ad_diag.py structure --change-date <改动日>` 看改动前后的类型花费占比）、阶段与目标 ACOS，对不上就先问用户，再进第 2 步。

## 执行顺序 = SOP 顺序

按诊断框架的 ① → ⑥ **依次下结论**：先外部（市场），再链接自身（②③ → ④⑤），**广告最后**。每一层的结论写完，再进下一层；后一层不能推翻前一层，只能补充。第⑥层的数据（terms / filter）**等 ④⑤ 有结论后才跑**，避免先看到广告问题就带偏判断——脚本会检查，缺 rootcause 文件时 terms / filter / harvest 直接拒绝运行。**一步一层**：每一步只跑这一层要用的命令，写完这一层的文件 / 结论，再进下一步。

## 第2步：准备 + 第①层 市场需求（外部，先做）
读 `references/diagnosis-framework.md`（判断标准）、`references/step2-compare.md` 2.1（trend 怎么跑）、`references/root-cause-agents.md`（外部模板）

1. **跑 `ad_diag.py trend`，这一步只取外部需要的输入**：脚本最后"第①层 市场需求（外部）输入"一段给出自身变化率 S（日/周/月）、**主周期**（由总订单判定自动选：持续下降 / 周升月降 → 月为主；近一周下降 → 周为主；单日波动 → 不深挖）、**异常起点**和起点前后对比窗口。②③ 的判定先不下结论。
2. **准备核心词和竞品**：核心词取资料里的；没有就用 `st_curr.csv` 花费/订单前 5。竞品资料里没有、用户也没给时，按 `root-cause-agents.md` 的方法找。
3. **派外部子代理**（Agent 工具，general-purpose，外部模板）：先比"起点前后两个窗口"的市场（核心词搜索量）和竞品（BSR / 价格 / Deal），再按主周期做日历周期对比，判定"市场降 + 竞品降 + 自己降"（偏 A）还是"市场稳 + 竞品稳/涨 + 自己降"（链接自身问题）→ 写 `rootcause_external.md`。子代理在跑的时候，主代理可以先读 trend 的 ②③ 部分，但**等外部结论回来再写 ②③ 的结论**。
4. **第①层结论**：一句话写进笔记。判为 A（跟随大盘）时，后面各层照样查，但动作以控成本、控库存为主，不建议加广告。

## 第3步：第②③层 销售拆解（链接自身）
读 `references/step2-compare.md`

1. **分周期看环比（step2-compare 2.3a）**：用第 2 步 trend 的输出，按 **日 → 周 → 月 → 年** 的顺序，每个周期单独写一句结论（哪些指标明显升 / 降）；"年"这句分两半：去年同期月环比（季节性）+ 年同比（整体水平）。判定**以脚本原文为准**。
2. **跨周期对比（2.3b）**：trend 的"跨周期一致性"表**整张照抄进报告**（所有行，差异解读一字不改，补充写在表下）。总订单那一行的差异解读（今年真的变差 / 偏季节性 / 近期才开始 / 单日波动…；季节性看"今年月环比 vs 去年同期月环比"，不看年同比）是这一步的主结论；再看其他指标和它一致还是矛盾，矛盾的地方写成异常点。表下必须写一句**"偏季节性的指标：…；今年真的变差的指标：…"**，一句话结论和第 7 步的主诊断都要用这个区分（例如"Sessions、自然订单的下滑偏季节性，去年同期也跌了约 34%；广告订单、点击是今年真的变差"），不能把季节性的下滑也算到今年的操作上。
3. **第②层**："流量降 / 转化降 / 双降 / 都没降"——决定第 4 步先查 ④ 还是 ⑤。
4. **第③层**：掉的是自然流量还是广告流量。广告流量先掉时，到 `op_log`（`ad_diag.py oplog`）找起点附近的操作——这是"广告操作引起的流量下降"，属于第③层的判断，不是第⑥层。
5. **第一个异常的变量**和 **⚠ 危险信号**（第 7 步判 D 时用）记下来。

## 第4步：第④⑤层 关键词权重 + 相对竞争力（内部）
读 `references/root-cause-agents.md`（内部模板），检查清单 `references/step3-root-cause.md` 由子代理去读

1. 派**内部子代理**（Agent 工具，general-purpose，内部模板），参数里带上第①层结论和第②③层结论：流量降重点查 ④，转化降重点查 ⑤，双降两个都查、⑤ 优先 → 写 `rootcause_internal.md`。两个子代理用同一组竞品。
2. 子代理只回传结论 + 缺失数据 + 要问用户的问题；它们不能直接问用户。

## 第5步：第⑥层 广告诊断（最后才做）
**先读完 `references/ads-diagnosis.md`，再跑 terms / filter**（四个结构、否词关联性检查、调价规则都在里面）

0. `terms` / `filter` 会检查数据目录里有没有 `rootcause_external.md` 和 `rootcause_internal.md`，没有就拒绝运行（SOP 顺序）。看到 ⛔ 就回去补前面的层，不要加 `--force` 绕过。
1. 跑 `ad_diag.py terms`（词结构有变化 → 先核对操作日志，放进第 6 步的合并提问）、`ad_diag.py filter`（`--target-acos` 用资料里的目标 ACOS，**不要用示例值**）、看广告位、新进花费词和烧钱不出单的词用西柚查关联性。
2. 这一层只记录广告问题，**不改变 ①–⑤ 的结论，不在这里定动作**；高 ACOS 词、搜索词结构变化不能拿来判 D。
3. 这一层要问用户的问题先记下，到第 6 步末尾合并一次问。

## 第6步：关键词机会（第⑥层之后，列候选）
读 `references/keyword-opportunities.md`

前五步找"为什么掉"，这一步找"**还有哪些词值得投**"，只列候选，第 7 步按诊断结果取舍。

1. **K1 收割词（必做）**：跑 `ad_diag.py harvest --curr st_curr.csv --prev st_prev.csv --target-acos <资料里的目标ACOS> --brand <自家品牌词>`：已出单、ACOS 达标、还没单独开精准的搜索词，带建议精准竞价和要加精准否定的来源活动。
2. **K2 冲刺词 / K3 竞品缺口词 / K4 市场词（西柚）**：按 ①–⑤ 的结论定先查哪个（流量问题先 K2、K3；转化问题 K2–K4 可以不查，第 7 步也会暂缓）。西柚这一步总共不超过 5 次调用；不可用时只做 K1，写明缺数据。
3. K2–K4 的候选按顺序过三关：**相关性 → 去重 → 可承受 CPC**（客单价 × 预估 CVR × 目标 ACOS），写 `keyword_opportunities.md`。
4. **合并提问**：①–⑥ 各层和这一步要问用户的问题合并去重，**一次问用户**。拿不到的数据**明确列出**，不要编。

## 第7步：诊断归类 → 广告动作 → 验证 → 输出
读 `references/output-format.md`

1. **按 ①→⑥ 写诊断路径**：每层一句结论，标出第一个异常的变量；市场对照表里**主周期那一行加粗**，结论按主周期写。
2. **归为四种诊断结果**（`diagnosis-framework.md`）：A 市场生命周期 / B 流量获取 / C 转化竞争力 / D 流量结构，可以主次叠加；都不命中就如实写"未发现明确的下滑原因"。**D 的硬条件**：trend 显示广告订单占比上升且自然订单下降，或输出了 ⚠ 危险信号；都不满足时诊断结果里不能出现 D（主、次都不行），搜索词结构和高 ACOS 词归第⑥层，写进动作表。 **偏季节性的指标不能算作某次操作或某个原因的结果**：跨周期表里判为"偏季节性"的指标（如 Sessions），在一句话结论和诊断结果里要写成"和去年同期一致（偏季节性）"，只有超出季节性的部分（"今年真的变差"的指标）才归到具体原因。写法示例："Sessions −34% 和去年同期一致（偏季节性）；今年额外的下滑来自广告订单、点击（比去年同期多降 xx pp），对应 10/18 关停定投"。
3. **按诊断结果匹配广告动作**（框架里的"诊断结果 → 广告动作 → 验证"表），每个动作写对象、参数、验证指标和复查日期；否词清单单独列。**关键词机会**按 `keyword-opportunities.md` 6.6 的"诊断结果 → 用哪些来源"取舍（C 类只用 K1，K2–K4 写"暂缓"），写进报告的"关键词机会"表，每个新词带止损规则。
4. **输出 + 存报告**：先写 `<skill目录>/data/ad-data/<ASIN>_<日期>/report.md`，**最后一条回复就是 report.md 的逐字内容**——只允许在末尾加一行文件路径，不得删列、删段、合并或改写；有上一次的报告就加一行"与上次相比"。 发出前自查：回复里必须有**跨周期表**和**用户说法核对表**，长度和 report.md 相当；少了任何一节、或明显比文件短，说明被压缩了，整段重贴 report.md 原文。
5. **写回记忆**：本次确认的新竞品、核心词、阶段或目标 ACOS 变化，问用户一句后写进 `<skill目录>/data/asin-profiles.md`。
