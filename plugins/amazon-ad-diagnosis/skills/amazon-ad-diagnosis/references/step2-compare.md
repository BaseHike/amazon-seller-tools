# trend：第①层外部输入 + 第②③层销售拆解 + 第一个异常的变量（第2、3步用）

判断标准见 `diagnosis-framework.md`。这一步只用 `daily.csv`，一个命令跑完。

## 2.1 跑 trend

```bash
python "<skill目录>/scripts/ad_diag.py" trend --file <skill目录>/data/ad-data/<ASIN>_<日期>/daily.csv --date <截止日期>
```

脚本开头如果提示 `⚠ sessions / total_orders … 有 N 天为空`，说明领星业务数据没回传完：含这些天的周期里总量类指标显示 `-`，日均和比率只用有数据的天算。提示"锚点日缺数据"时，把 `--date` 往前挪一天重跑，报告里写明实际截止日。

脚本提示 `⚠ budget 只有 N 天有值`：领星只给了当前预算，预算和预算使用率只看今日，报告里不要写预算的周 / 月变化。README.txt 写明历史预算是用当前预算回填的（旧版拉数据的格式），同样处理：表里预算的周 / 月变化不能用。

脚本提示 `⚠ 疑似大促/异常日`（售价比中位数低 10% 以上，或 Sessions ≥ 中位数 2 倍，如 Prime 会员日）：报告里写明这些日期，月环比同时写脚本给的"去掉这些天后的月环比"；第一个异常变量的基准已经自动去掉这些天。

周期定义（锚点 = 截止日期 D）：
| 周期 | 本期 | 对比期 |
|---|---|---|
| 日环比 | D | D−1 |
| 上周同日 | D | D−7（排除周几效应） |
| 周环比 | D−6 ~ D | D−13 ~ D−7 |
| 月环比 | D−29 ~ D | D−59 ~ D−30 |
| 7天同比（年） | D−6 ~ D | 去年同期：上面日期 − 364 天（`daily_ly.csv`） |
| 30天同比（年） | D−29 ~ D | 去年同期：上面日期 − 364 天 |
| 去年同期月环比 | 去年 D−29 ~ D | 去年 D−59 ~ D−30（都是 − 364 天）——判断季节性用 |

没有 `daily_ly.csv`（新品不满一年、没拉）时，同比列是 `-`，跨周期解读会写"缺年同比，分不清季节性"，报告照实写。

## 2.2 指标定义

| 指标 | 公式 | 说明 |
|---|---|---|
| **日均流量** | Sessions 日均 | 诊断框架的 Traffic |
| **整体 CVR** | 总订单 ÷ Sessions | 诊断框架的 CVR |
| 曝光 | Σ impressions | 广告 |
| 预算 / 预算使用率 | Σ budget；花费 ÷ 预算 | 使用率 >90% 说明可能提前花完，曝光受限 |
| 点击、CTR | Σ clicks；点击 ÷ 曝光 | |
| CPC | 花费 ÷ 点击 | |
| CPM | 花费 ÷ 曝光 × 1000 | 竞争变激烈时先涨 |
| 广告订单、广告 CVR | Σ ad_orders；广告订单 ÷ 点击 | |
| ACOS | 花费 ÷ 广告销售额 | |
| TACOS | 花费 ÷ 总销售额 | 广告对整体的依赖度 |
| 自然订单 | 总订单 − 广告订单 | 广告订单有归因窗口，近 1–2 天偏低，日环比要谨慎 |
| 自然点击（近似） | Sessions − 广告点击 | Sessions 不等于点击，只看趋势 |
| 自然转化率 | 自然订单 ÷ 自然点击 | |
| 自然曝光 / 自然点击率 | SQP 总曝光 − 广告曝光；自然点击 ÷ 自然曝光 | 没有 SQP 数据就标"缺数据"，不要估 |
| 广告订单占比 | 广告订单 ÷ 总订单 | 第⑥层危险信号要看它 |

## 2.3 判定上升/下降

脚本给每个指标打标，**报告直接用脚本的原文**：
- 阈值：日 ±20%、周 ±15%、月 ±10%；订单类指标在本期订单 <30 时阈值翻倍（样本小）。
- **持续下降/上升**：周和月同向超阈值 → 结论可信；只有日变化 → "单日波动，观察"。
- **周升月降 / 周降月升**：周和月方向相反 → 两个周期都要写，**不能只用本周结论**。月度下滑是主线，本周反弹只是"近期有改善"。
- 比率类（CVR/CTR/ACOS）看相对变化，不看百分点差。

## 2.3a 分周期看环比（第 3 步先做，逐个周期写结论）

按 **日 → 周 → 月 → 年** 的顺序，每个周期单独写一句：这个周期里哪些指标明显升、哪些明显降（只看超阈值的，用 trend 表里对应那一列）。
- **日**（日环比 + 上周同日）：只用来发现突发事件，不单独下结论。
- **周**（周环比）：最近的变化。
- **月**（月环比）：主线趋势；有大促日时同时写"去掉这些天后的月环比"。
- **年**：两件事分开写——① 去年同期月环比：去年这个时候是不是也这样变（判断季节性）；② 7 天 / 30 天年同比：整体水平比去年高还是低（长期趋势）。没有去年数据就写"缺去年同期数据"。

## 2.3b 跨周期对比：差异和问题（脚本"跨周期一致性"部分）

脚本把关键指标在日 / 周 / 月 / 年四个周期的方向放在一行，并按下面的规则给出"差异解读"。**解读以脚本原文为准**，再补一句它说明了什么问题、下一步查哪一层：

**季节性怎么判断**：看"今年月环比"和"去年同期月环比"（去年这个时候自己的环比）。去年同期也这样变 → 季节性；今年比去年同期多变差 10 个百分点以上 → 超出季节性的部分是今年的问题。**年同比不能用来判断季节性**：它只说明整体水平比去年高还是低，产品在增长期时年同比会一直为正。

| 情况（按"朝不利方向"算） | 脚本解读 | 说明什么 |
|---|---|---|
| 月变差，去年同期也差不多这样变 | 偏季节性 | 第①层核对去年同期市场；动作以控成本为主，不要为了"救量"加广告 |
| 月变差，比去年同期多变差 ≥10pp | 今年真的变差（写出多变差几个点） | 超出季节性的部分往 ②–⑤ 找今年的变化 |
| 月变差，没有去年数据 | 分不清季节性 | 靠第①层外部数据判断 |
| 只有周变差 | 近期才开始 | 找最近一周的操作 / 竞品动作 |
| 周升月降 | 本周已回升，月度仍是主线 | 两个都写，结论按月 |
| 只有日变差 | 单日波动 | 观察，不下结论 |
| 年同比变差（附加） | 长期偏弱 | 问题不是这个月才有，看更长的历史 |

表下写一句"偏季节性的指标：…；今年真的变差的指标：…"，结论和主诊断都按这个区分。

**同一张表里不同指标会给出不同答案，这正是要找的东西**：例如 Sessions、自然订单"偏季节性"，而广告订单、点击"今年真的变差" → 大盘季节性带走了自然流量，额外的下滑来自今年的广告收缩。

写完"总订单"这一行的结论后，看其他指标和它**一致还是矛盾**：例如总订单月降，但整体 CVR 月升、Sessions 月降 → 问题在流量，不在转化（和第②层对上）；曝光月升、点击月降、CTR 月降 → 流量变泛或主图 / 价格吸引力下降。矛盾的地方就是要查的问题，写进异常点。

## 2.4 第②③层判定（脚本"诊断框架分层判定"部分）

周、月各给一次：
- **第②层**：日均流量和整体 CVR 哪个降了 → 流量获取问题 / 转化竞争力问题 / 双重恶化（先修转化）/ 小幅叠加 / 都没降。
- **第③层**：日均自然点击（近似）和广告点击哪个降了 → 自然降查第④层；广告降先到 op_log 找起点附近的广告操作（这是第③层的判断），第⑥层留到最后。
- **⚠ 危险信号**：广告订单稳定、自然订单下降、广告订单占比上升 → 记下来，第 7 步偏 D 类。

周和月结论不一样时，以月为主线、周为"近期变化"，两个都写进报告。

## 2.5 第一个异常的变量（脚本最后一部分）

脚本把近 30 天每个变量的 7 天滚动均值和基准期（D−59 ~ D−30 的日均）比，**连续 3 天超阈值**才算异常，按首次异常时间排序：
- 排最前的就是**第一个异常的变量**，诊断从它所在的层开始（流量 → ②③，CVR / 价格 / 评分 → ⑤，广告曝光 / 点击 / CPC → ⑥，库存 → Listing 因素）。
- 到 `op_log.csv` 找这个时间段前后的操作（关活动、改预算、改竞价），找到了就写进报告作为证据。
- 几个变量同一时间段出现时都列出来，再看哪个能解释其他的（比如广告点击先掉 → Sessions 掉 → 订单掉）。
- 基准期本身已经在下滑时，真实起点可能更早，报告里注明。

## 2.6 第①层外部输入（脚本最后一段，第2步先用）

SOP 先做外部，所以第 2 步跑完 trend **先看最后一段**"第①层 市场需求（外部）输入"，原样交给外部子代理：
- **自身变化率 S**：总订单日 / 周 / 月环比。
- **主周期**：由总订单的判定自动选——持续下降、周升月降、月度下降 → 月为主；近一周下降、周降月升 → 周为主；单日波动 → 不深挖；没下降 → 只做背景确认。
- **异常起点**和**起点前后对比窗口**（各 14 天，起点前窗口已去掉大促日）：外部先在这两个窗口比市场和竞品，再做日历周期对比。

②③ 层的结论等外部结论回来后（第 3 步）再写。
