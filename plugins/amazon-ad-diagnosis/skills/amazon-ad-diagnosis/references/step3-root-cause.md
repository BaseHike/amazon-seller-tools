# 第①④⑤层检查清单（第2步外部、第4步内部子代理用）

**执行方式**：主代理按 `root-cause-agents.md` 依次派两个子代理：第2步外部（先做），第4步内部。**外部子代理**查 3.1–3.2（第①层 市场需求）；**内部子代理**查 3.3–3.5（第④层 关键词权重、第⑤层 相对竞争力、Listing 因素）。都按 3.6 的格式回传。判断标准见 `diagnosis-framework.md`。

先看前面各层给的线索，按诊断框架只查相关的层：第②层是"流量降"就重点查 ④，"转化降"就重点查 ⑤，"双降"两个都查、⑤ 优先；第一个异常的变量落在哪层，就先查哪层。每一项写清：**数据来源、有无变化（数值 + 日期）、对哪个指标有影响**。拿不到的数据列入"需用户提供"，不要推测成事实。

## 3.1 第①层 市场需求（外部子代理）

| 维度 | 看什么 | 数据来源（西柚 MCP，拿不到再用浏览器 / 网页搜索） |
|---|---|---|
| 类目趋势 | 类目整体销量、销售额同期变化；细分市场看竞品或头部的大类排名 | `get_category_market_size_trends`、`get_category_sales_ranking` |
| 搜索需求 | 核心词搜索量、ABA 排名趋势 | `get_keyword_aba_trends`、`get_keyword_info` |
| 竞品表现 | 主要竞品的销量 / 排名是否同步下降，有没有降价、Deal、广告加码 | `get_asin_bsr_trends`、`get_asin_info_change_trends`、`get_asin_ad_change_trends` |
| 季节性 | 是否进入淡季 / 旺季、节假日前后 | `get_category_seasonality` |
| 新品冲击 | 类目里有没有新品快速起量 | `get_category_new_release_ranking` |
| 竞争强度 | CPM / CPC 上涨而自身 CTR / CVR 不变 | trend 结果 + `get_keyword_advertising_replay` |

西柚工具是延迟加载的，先用 ToolSearch 加载，调用时填 user_task / intent_summary。西柚按次扣 credits：列表类工具 page_size ≤ 10，不调用 generate_category_insight_resource 这类单次几百 credits 的报告工具（用户同意除外）。

## 3.2 第①层判定：市场在跌，还是只有自己在跌

**先定看哪段时间**（trend 最后一段给出，原样用）：

| 总订单的 trend 判定 | 主周期 | 辅助 | 外部要回答 |
|---|---|---|---|
| 持续下降 | 月 | 周 | 大盘这个月是不是也在跌、跌了多少 |
| 周升月降 | 月（主线） | 周 | 月度下滑是不是大盘带的；本周回升是大盘回暖还是自己调整的结果 |
| 近一周下降 / 周降月升 | 周 | 月（背景） | 这周大盘有没有突然下跌（节后、竞品大促） |
| 月度下降 | 月 | 周 | 是不是季节性 / 缓慢下行 |
| 单日波动 | 不深挖 | 周、月 | 只确认大盘稳定，省 credits |

**最有说服力的是"起点前后"对比**：在异常起点前后各 14 天，比较市场和竞品有没有同时变化（例如竞品恰好在起点降价、上 Deal）。先做这个，再做日历周期对比。

**数据粒度**：ABA 搜索量是周；类目市场规模一般是 30 天 / 月，判断不了周，周级别用核心词搜索量和竞品；竞品 BSR / 价格是日，最适合对照异常起点。

对同一周期（日 / 周 / 月）比较：市场变化率 M（类目销量或核心词搜索量，写明用的哪个）、竞品变化率 C（竞品销量或 BSR）、自己变化率 S（总订单）。

| 情况 | 判定 |
|---|---|
| M、C、S 都降，且 \|S−M\| < 10 个百分点 | 跟随大盘 → 偏生命周期 / 季节性（诊断结果 A） |
| M 稳 / 涨，C 稳 / 涨，S 降 | 跑输大盘、份额被抢 → 链接竞争力问题，交给 ②–⑤ |
| M 降，S 降得更多 | 大盘 + 自身问题叠加 |
| M 降，S 稳 / 涨 | 跑赢大盘 |

西柚数据为第三方估算，日级别波动大，日对比只作参考，结论以周 / 月为准。

**拿不到西柚数据时**（MCP 不可用、被拦截、无额度）：先用浏览器看亚马逊前台、网页搜索补市场和竞品数据（标明来源，可信度最高"中"）。仍然拿不到时：
- 不能跳过本层，市场对照表照常输出，市场列填"缺数据"，结论填"无法判定"。
- 必须问用户具体问题，例如："你看到的类目 / 核心词（列出 2–3 个）最近一个月搜索量、竞品价格和 Deal 有没有明显变化？"
- 外部因素一律标"未验证"，可信度不得高于"低"。也不能因为没有外部数据，就把原因全部归到内部。

## 3.3 第④层 关键词权重（内部子代理）

自然排名下降只是现象。要回答：**这个词下面，为什么失去了持续拿订单的能力？**

| 看什么 | 数据来源 |
|---|---|
| 核心词自然排名、广告排名的变化和开始日期 | 西柚 `get_asin_keyword_rank_trends`（必要时 `get_asin_keyword_rank_hourly`） |
| Top 10 / Top 20 关键词数量 | 西柚 `get_asin_keyword_count_trends` |
| 自然关键词覆盖、核心词流量占比 | 西柚 `get_asin_keyword_traffic_trends`、`get_asin_keywords` |
| 关键词订单密度（核心词的订单 ÷ 点击，本期 vs 上期） | st_curr.csv / st_prev.csv；西柚 `get_asin_keywords` |
| 广告结构偏移（核心词花费占比 ↓、泛词 ↑） | st_curr.csv / st_prev.csv |

排名掉的原因归到三类之一：关键词转化下降（订单密度 ↓）、广告结构偏移（核心词 ↓ 泛词 ↑）、相对竞争力下降（交给 3.4 一起看）。

## 3.4 第⑤层 相对竞争力（内部子代理）

转化是**相对竞争**：每一项都要**自己和竞品对比**，只看自己没变不算结论。

| 维度 | 看什么 | 数据来源 |
|---|---|---|
| 价格 | 售价、Coupon、Promotion，自己 vs 竞品，有没有被竞品降价或加券 | daily.csv price；西柚 `get_asin_info_change_trends`；浏览器看前台 |
| 信任 | Rating 是否掉档（4.5→4.3 影响明显）、Review 数量和增速 vs 竞品、近期差评内容 | daily.csv rating；领星评论；西柚 `get_asin_info`；浏览器 |
| 页面 | 主图 / 视频 / A+ / 卖点是否改过、被平台替换，竞品有没有升级页面 | 西柚 `get_asin_info_change_trends`；浏览器；问用户 |
| 产品 | 功能 / 材质 / 套装 / 差异化，竞品有没有升级或推新品 | 浏览器看竞品页面；西柚 `get_category_new_release_ranking` |

## 3.5 Listing 因素（内部子代理，按需查）

| 因素 | 看什么 | 影响的层 | 数据来源 |
|---|---|---|---|
| 库存 / 配送 | 断货、库存低被限流、配送时效变长 | 流量、CVR | daily.csv inventory；领星 FBA 库存 |
| Buy Box | 是否丢购物车、跟卖 | 流量（广告不展示）、CVR | 领星 Listing；浏览器；问用户 |
| 变体 | 父子体被拆分 / 合并、评论被拆 | CVR、自然排名 | 西柚 `get_asin_variations` |
| 标题 / 五点 / 类目 | 是否被改、是否丢关键词、类目节点变化 | 自然流量 | 西柚 ASIN 变化；问用户 |
| 账户 / Listing 健康 | 抑制、违规、品牌备案变化 | 全部 | 问用户 |
| 退货率 / 质量问题 | 退货原因集中 | 评分、CVR | 领星退货分析 |

广告操作（竞价、预算、关活动）由主代理在第⑥层看，内部子代理不用查。

## 3.6 结论格式

每层先写一句结论（有无异常、往哪层继续），再列原因。每个原因一行：
`[第N层] 原因 — 证据（数据+来源）— 影响指标 — 可信度（高/中/低）`
按影响大小排序，最多 5 个主因。
