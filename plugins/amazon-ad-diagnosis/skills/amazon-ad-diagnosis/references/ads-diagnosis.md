# 第⑥层：广告诊断（第5步：④⑤ 有结论后，主代理最后做）

诊断框架里广告**最后才看**。这一层只找出广告结构里的问题、记下证据，**广告动作等第 7 步定了诊断结果再匹配**，不在这里给。判断标准见 `diagnosis-framework.md` 第⑥层。

## 6.1 四个结构

| 结构 | 看什么 | 数据 |
|---|---|---|
| 流量结构 | 核心词占比 ↓、泛词占比 ↑；搜索词覆盖 | `terms` 输出、st_curr / st_prev |
| 订单结构 | 高相关词订单 ↓、低相关订单 ↑ | `terms` 输出 + 6.4 关联性结论 |
| 成本结构 | CPC ↑、CPA（花费 ÷ 广告订单）↑、CPM ↑ | trend 输出、campaigns_daily.csv |
| 位置 / 预算结构 | 首页顶部 / 其余位置 / 商品页的花费和订单占比变化；预算使用率 >90% 的活动；预算是否压在低效活动上 | placement.csv、campaigns_daily.csv（budget 只有截止日有值时只看当天） |

- CPM 涨而 CTR、CVR 不变 → 竞争加剧（外部），写进报告并交给第①层的结论一起看。
- 预算使用率接近 100% 且曝光降 → 预算限制。
- 广告位：用 `placement.csv` 按本期 / 上期汇总各位置的花费占比、ACOS、CVR，占比变化超过 10 个百分点的写出来。没有这个文件就标"缺数据"。placement 是活动级数据（含同一活动里的其他 ASIN，只有 SP），只作结构信号，不当成这个 ASIN 的精确数据。

## 6.2 搜索词结构变化

```bash
python "<skill目录>/scripts/ad_diag.py" terms --prev <skill目录>/data/ad-data/.../st_prev.csv --curr <skill目录>/data/ad-data/.../st_curr.csv
```

脚本判定"结构变化"的信号（任一命中）：
- 本期花费 Top10 词与上期 Top10 重合率 < 60%
- 新出现的词（上期没有）花费占比 > 20%
- 匹配方式花费结构变化 > 10 个百分点（如广泛占比从 30% → 50%）
- 花费集中度（Top10 占比）变化 > 15 个百分点

**结构有变化 → 先对照 `op_log.csv`，再把问题记下来**："本期搜索词结构变了（具体说明），这段时间广告策略有没有调整？（新开活动、改匹配方式、改竞价策略、加/删词）"。这个问题和两个子代理带回的问题**合并成一次问**（SKILL 第6步最后一条），不要单独先问。问的时候把日志里找到的操作（日期 + 活动）列出来，让用户逐项确认。
- 用户确认是主动调整 → **先核对，再放行**：把用户说的每项调整（改匹配、关定投、降预算等）在 `op_log.csv` 和 `campaigns_daily.csv` 里找到对应的**日期 + 活动**，列一张"用户说法 ↔ 日志记录"对照表写进报告。
  - op_log 只有按天汇总（README 写明，看不出改了什么字段）→ 按日期 + 活动对，再用 `campaigns_daily.csv` 当天前后有花费的活动数、花费、预算变化佐证。
  - 对得上 → 用 `campaigns_daily.csv` 比较调整日前后各 7 天相关活动的花费、订单、ACOS、CVR（**按 campaign_id 汇总**，活动改名后名字不同），同时看 daily.csv 的 Sessions 和自然单，评估新结构效果，不当成异常。
  - 对不上（日志里没有、日期不同、范围不同，如一次关停了大量活动用户没提）→ 把差异写进合并提问问清楚，不要直接采信用户说法。
- trend 找到的**第一个异常变量的时间段**，必须对照这段时间前后的操作记录，判断是不是那次操作引起的。
- 用户说没调整 → 视为流量漂移，继续 6.3。

## 6.3 组合筛选（具体浪费在哪）

```bash
python "<skill目录>/scripts/ad_diag.py" filter --file <skill目录>/data/ad-data/.../st_curr.csv --target-acos <目标ACOS> --out <skill目录>/data/ad-data/.../筛选结果.xlsx
```

`<目标ACOS>` 取 asin-profiles.md 里该 ASIN 的目标 ACOS，写 55%、55 或 0.55 都行（脚本都按 55% 算）。**不要用示例值**；记忆里没有目标 ACOS，先回第 1 步问。

规则：烧钱不出单 / ACOS 超标（给建议竞价）/ 低效高曝光 / 优质词（已在投的词加价；还没单独开精准的出单词由第 6 步 `harvest` 列出）。新竞价 ≈ 当前 CPC × 目标ACOS ÷ 实际ACOS，单次调幅 ≤30%。这些是**候选**，第 7 步按诊断结果决定用不用。

## 6.4 无关词关联性检查（西柚）

对象：`terms` 列出的"新进花费词"+ 6.3 里"烧钱不出单"的词。词很多时只取花费前 20。

西柚 MCP 的工具是延迟加载的：先用 ToolSearch 搜 `get_asin_keywords get_keyword_info find_related_keywords`（搜不到再按 intake 1.2 宽泛找一次），用 select: 一次性加载要用的工具。列表类工具 page_size ≤ 20。搜不到或调用被拒 → 关联性结论填"缺西柚数据，待人工判断"，否词只按点击/花费/订单给"候选"，并告诉用户。

逐词判断，按需调用西柚 MCP（调用时按服务要求填 user_task / intent_summary）：
1. `get_asin_keywords`（自己的 ASIN，filters 里用 searchTerm 一次传多个词）：该词是否已是自己的自然/广告流量词、有没有出单记录 → 有则相关。**searchTerm 过滤是包含匹配**（传 magnesio 会返回所有含 magnesio 的词），只认和待查词**完全相同**的那一行；没有完全相同的行 = 不是自己的流量词。
2. `get_keyword_asin_analysis` 或 `get_keyword_info`：该词下排名靠前的 ASIN 是不是同类产品；搜索量和点击集中度。
3. `find_related_keywords`：该词与自己核心词是否同一语义簇。

结论三类：
- **相关且可能转化** → 保留，降竞价观察或放到单独活动。
- **弱相关**（同场景不同品类）→ 降竞价 50% 观察 1–2 周。
- **不相关 / 不会转化** → 否词候选（精确否定；词根明显无关的用词组否定）。

新品期的核心大词即使暂时 0 单也不否，改为降价。
