# 第6步：关键词机会（第⑥层之后、诊断归类之前）

前五步回答的是"为什么掉"，这一步回答"**还有哪些词值得投**"。这一步只**列候选**，用不用、投多少，第 7 步按诊断结果决定（见 6.6 表）。和 filter 的"优质词"不同：filter 看的是**已经在投**的词要不要加价，这里找的是**还没单独投**的词。

四个来源，按证据强弱排序；证据越强，越先用：

| 来源 | 是什么 | 证据 | 数据 |
|---|---|---|---|
| K1 收割词 | 自动 / 广泛 / 词组 / 类目活动里已经出单、ACOS 达标，但还没有单独开精准的搜索词 | 自己的真实订单（最强） | `ad_diag.py harvest`（st_curr + st_prev） |
| K2 冲刺词 | 自己已经有自然排名（第 4–20 位）的相关大词，推一把就能上首页 / 首屏 | 自己的自然排名 | 西柚 `get_asin_keywords`（自己的 ASIN） |
| K3 竞品缺口词 | 2 个以上主要竞品有流量、自己没有或排名在 50 名以外的高相关词 | 竞品的真实流量 | 西柚 `get_multi_asin_keyword_comparison` |
| K4 市场词 | 核心词延伸出的高相关长尾词，搜索量、转化达标，趋势在涨 | 市场数据（最弱） | 西柚 `find_related_keywords` + `get_keyword_info` |

## 6.1 K1 收割词（必做，只用领星数据）

```bash
python "<skill目录>/scripts/ad_diag.py" harvest --curr <skill目录>/data/ad-data/.../st_curr.csv --prev <skill目录>/data/ad-data/.../st_prev.csv --target-acos <目标ACOS> --out <skill目录>/data/ad-data/.../关键词收割.xlsx
```

- 两期合并算（14 天），一周数据太少。`--target-acos` 和 filter 一样取资料里的目标 ACOS，**不要用示例值**。
- 规则：订单 ≥ 2（`--min-orders` 可改）、ACOS ≤ 目标 ACOS，且**还没有**同一个词的精准投放 → 收割候选。两期都出单的标"稳定"，优先。
- 脚本给出：建议精准竞价（= 每次点击销售额 × 目标 ACOS，限制在当前 CPC 的 0.7–1.3 倍）、来源活动（收割后要在这些活动里**加精准否定**，避免自己跟自己抢）。
- 搜索词本身是 ASIN（B0 开头）的 → "ASIN 定投候选"，单独列。
- 只出了 1 单的词数据不够，列进"观察"，不收割。
- 已经有精准投放的出单词不重复建，要不要加价看 filter 的"优质词"。
- `--brand` 传资料里的"品牌词（自家）"：自家品牌词标"自家品牌"，属于品牌防守，单独写一行，不算拓流量。
- 只有一个词的品类大词（如 `magnesium`）即使达标，CPC 高、波动大，先用建议竞价小预算开精准，7 天后再看。
- K1 的词已经被自己的真实订单证明相关，不用再过 6.5 的相关性关。

## 6.2 K2 冲刺词（西柚）

1. `get_asin_keywords`（自己的 ASIN，`sort_field=traffic`，page_size 50）。如果第4步内部子代理已经查过核心词排名（看 `rootcause_internal.md`），直接用，不重复调用。
2. 选**自然排名 4–20**、流量排在前 50、和产品高相关的词。
3. 第④层发现"核心词自然排名下降"的词，也放进 K2，标"排名下降"。
4. 去掉 st_curr / st_prev 里已经有精准投放的词（已在投的看 filter）。

## 6.3 K3 竞品缺口词（西柚）

1. `get_multi_asin_keyword_comparison`：自己 + 第①层用的那组竞品（最多 4 个），`sort_field=traffic`，page_size 50。
2. 选：**2 个以上竞品**在这个词下有流量（自然或广告），自己没有流量或排名在 50 名以外。
3. 竞品的品牌词单独列成"竞品品牌词"，默认不投；用户明确想打竞品品牌时才放进候选。

## 6.4 K4 市场词（西柚，可选）

1. `find_related_keywords`：种子词用资料里的核心词（1–2 个），`reference_asins` 传自己 + 竞品（至少 2 个），只要 `correlationTier` 为 strong / high 的，pageSize 50。
2. 用 `get_keyword_info` 给 K2–K4 的候选**一次性**补指标（一次最多 100 个词）：周搜索量、点击转化率、建议竞价（CPC）、竞争难度、Top3 点击份额。
3. 趋势要看时用 `get_keyword_aba_trends`（近 12 周）。只在旺季涨的词，第①层判为偏季节性时不当成机会。

西柚按次扣 credits：这一步西柚总共**不超过 5 次调用**，列表类 page_size ≤ 50。单次几百 credits 的报告类工具不用。西柚不可用时，只做 K1，报告里写"K2–K4 缺西柚数据"。

## 6.5 筛选：相关性 → 去重 → 算得过来

每个 K2–K4 候选按顺序过三关，不过就删，删的原因写进附录：

1. **相关性**（先于数据）：和产品的成分、剂型、规格、人群、用途一致。属性冲突的（剂型不同：胶囊 vs 粉剂 / 软糖；人群不同：儿童 vs 成人；规格、用途明显不同）删掉。拿不准的标"弱相关"，只能进测试。
2. **去重**：已经在 st_curr / st_prev 里有精准投放的、K1 已经列过的、用户说过否掉或测过不行的，删掉。
3. **算得过来**：**可承受 CPC = 客单价 × 预估 CVR × 目标 ACOS**。
   - 客单价用 daily.csv 近 30 天的总销售额 ÷ 总订单。
   - 预估 CVR 取"西柚点击转化率"和"自己近 30 天广告 CVR（trend 输出）"里**较小**的那个（西柚是全市场数，偏乐观）。
   - 西柚建议竞价 > 可承受 CPC × 1.3 的词，删掉或标"成本过高"；在 1–1.3 倍之间的标"偏贵，只能低价测"。

再按搜索量分层：周搜索量高的大词（K2 为主）只开精准；长尾词可以合并到一个词组活动里测。

## 6.6 诊断结果 → 用哪些来源（第 7 步用）

关键词机会是**加流量**的动作，只有在诊断结果需要恢复流量时才放大；转化有问题时，加进来的流量也转化不了。

| 诊断结果 | 用哪些来源 | 怎么用 |
|---|---|---|
| A 市场生命周期 | 只用 K1 | 把预算从低效词挪到已验证的收割词，**不新增测试词** |
| B · 核心自然流量 ↓ | K2 优先（尤其"排名下降"的核心词），再 K1 | 核心词单独开精准，首页顶部溢价小步加；K3 少量测 |
| B · 广告流量 ↓ | K1 + K3，K4 少量 | 恢复高质量付费流量；新词放单独测试活动 |
| C 转化竞争力 | 只用 K1 | K2–K4 等价格 / 页面 / 竞争力修好、CVR 回升后再做，报告里写明"暂缓" |
| D 流量结构 | K2 核心词精准 + K1 | 预算给核心词精准，**不加泛词、不开新的广泛** |
| 未发现明确原因 | K1 + K3 / K4 小预算测试 | 测试活动日预算 ≤ 总预算 10% |

偏季节性的下滑（跨周期表判"偏季节性"）不靠拓词解决，K3 / K4 不因为季节性下滑而放大。

## 6.7 投放规则（写进动作表的参数）

- K1：在现有精准活动（或新建"收割-精准"活动）加精准词，竞价用脚本的"建议精准竞价"；同时在来源活动加**精准否定**。
- K2：精准，竞价从"可承受 CPC"起，单次调幅 ≤ 30%；需要冲首页时首页顶部溢价从 +20% 起。
- K3 / K4：单独的测试活动（精准或词组），竞价 = min(西柚建议竞价, 可承受 CPC)，日预算 ≤ 总预算 10%。
- **止损规则**（每个新词都写）：点击数 ≥ 1.5 ÷ 预估 CVR 还没出单 → 暂停或否定；14 天 ACOS > 目标 ACOS × 1.3 → 降价 30% 或停。
- 复查：执行后第 7 天看点击和花费，第 14 天看订单和 ACOS。

## 6.8 写进文件

写 `<skill目录>/data/ad-data/<ASIN>_<日期>/keyword_opportunities.md`：

| 来源 | 关键词 | 相关性 | 证据（订单 / ACOS / 自然排名 / 竞品覆盖 / 周搜索量 / 转化率） | 可承受 CPC | 建议投放（活动 / 匹配 / 竞价 / 否定） | 止损 |
|---|---|---|---|---|---|---|

表下写：西柚调用了哪些工具、几次；删掉的词和原因（附录）；要问用户的问题（并入合并提问）。

这一步**不定**哪些词一定要投，第 7 步按 6.6 取舍后写进报告"四、动作"的"关键词机会"表。
