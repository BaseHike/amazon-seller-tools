# 外部 / 内部两个子代理（第2步外部、第4步内部，给主代理用）

按 SOP **依次**派两个子代理：第2步先派**外部**（第①层 市场需求）；外部结论回来、第3步写完 ②③ 结论后，第4步再派**内部**（第④层 关键词权重 + 第⑤层 相对竞争力 + Listing 因素）。`subagent_type: "general-purpose"`，description 分别写"外部：市场需求""内部：关键词与竞争力"。把下面对应的模板整段复制进 prompt，替换 `{{...}}`。第⑥层广告诊断（`ads-diagnosis.md`）等内部结论回来后才做。

子代理**不能和用户对话**。缺的数据、要问用户的问题都写进结果里带回来，由主代理统一问。

---

## 主代理先准备的参数

| 参数 | 从哪来 |
|---|---|
| `{{用户原话}}` | 用户发起这次任务的原始问题，逐字照抄（西柚的 user_task 要用） |
| `{{ASIN}}` `{{父体ASIN}}` `{{站点}}` `{{截止日期}}` | 第1步（截止日期写实际用的那天） |
| `{{数据目录}}` | `<skill目录>/data/ad-data/<ASIN>_<日期>/` 的**绝对路径** |
| `{{skill目录}}` | 本 skill 加载时给出的 Base directory |
| `{{前序结论}}` | 派外部时写"无"（外部是第一层）。派内部时 3–6 行：第①层结论、第②层判定（周 / 月）、第③层判定、第一个异常的变量和时间段、op_log 里对应的操作、是否有危险信号 |
| `{{用户已确认的情况}}` | 用户说过的近期改动、促销、阶段等要点；没有写"无" |
| `{{自身变化率}}` | trend 输出里"总订单"的日 / 周 / 月环比 |
| `{{主周期}}` `{{异常起点}}` | trend 输出最后一段"第①层 市场需求（外部）输入"：主周期（及要回答的问题）、异常起点和起点前后对比窗口，原样抄 |
| `{{核心词}}` | asin-profiles.md 里记录的核心词 + `st_curr.csv` 里本期花费 / 订单前 5 的搜索词（用 python 按 search_term 汇总，不用等第⑥层的 terms），合并去重 |
| `{{竞品ASIN}}` | asin-profiles.md 里的竞品，或用户这次给的；都没有时主代理按下面"找竞品"的方法找。**两个子代理用同一组** |

**找竞品**（记忆里没有、用户也没给时，主代理在派子代理前做）：
1. 广告里已经在打的竞品：`st_curr.csv` 里像 ASIN 的搜索词（b0 开头），以及活动 / 广告组名里的品牌或 ASIN（ASIN 定投组投的就是竞品，如"ASIN-竞品品牌A"）。
2. 西柚 `get_keyword_asin_analysis`（page_size ≤ 15）查两个词：**最能代表产品的特征词**（带规格或卖点的，如 magnesium 7 complex），和流量最大的大词。只取同类型、价格在自己 ±40% 以内的。
3. 两边合并去重，取 5–8 个。先用这组派子代理，合并提问时请用户确认，确认后写进记忆。

## 外部子代理 Prompt 模板（第①层 市场需求）

```
你的任务：判断一个亚马逊 ASIN 的销量下滑，是市场整体在跌，还是只有它自己在跌（诊断框架第①层）。只做判断，不给优化建议，不执行任何修改。

参数
- 用户原话：{{用户原话}}
- ASIN：{{ASIN}}（父体 {{父体ASIN}}），站点：{{站点}}，截止日期：{{截止日期}}
- 数据目录：{{数据目录}}
- 前面各层的结论：{{前序结论}}
- 自身变化率（总订单）：{{自身变化率}}
- 主周期：{{主周期}}
- 异常起点和起点前后对比窗口：{{异常起点}}
- 核心词：{{核心词}}
- 竞品 ASIN：{{竞品ASIN}}

做法
1. 先读 {{skill目录}}/references/diagnosis-framework.md 的"① 市场需求"，再读 {{skill目录}}/references/step3-root-cause.md 的 3.1、3.2、3.6。
2. 西柚 MCP 是延迟加载的：先用 ToolSearch 加载要用的工具。每次调用都填 user_task = 上面的"用户原话"（逐字），intent_summary = 这次调用要查什么。站点用上面的站点，时间按截止日期往前取。西柚按次扣 credits：列表类工具 page_size ≤ 10；**不要调用 generate_category_insight_resource 这类单次几百 credits 的报告工具**（要用就写进"需要问用户的问题"）；有 get_account_credit_quota 就先看余额，余额 < 200 时只查市场、搜索需求、竞品三项。
   - 类目趋势：先用 get_asin_info 或 search_market_insight_categories 确定类目，再用 get_category_market_size_trends、get_category_sales_ranking
   - 搜索需求：先用 get_asin_keywords 取自己 ASIN 自然流量前 5 的词，和上面的核心词合并去重；再用 get_keyword_aba_trends、get_keyword_info 看搜索量和 ABA 排名趋势
   - 竞品表现：get_asin_bsr_trends、get_asin_info_change_trends、get_asin_ad_change_trends，看竞品销量 / 排名是否同步下降、有没有降价 / Deal / 广告加码
   - 季节性：get_category_seasonality；新品冲击：get_category_new_release_ranking
   - 竞争强度：结合 trend 输出的 CPM / CPC 变化和 get_keyword_advertising_replay
3. **先比起点前后**：在 {{异常起点}} 给出的前后两个窗口，比较市场（核心词搜索量）和竞品（BSR / 价格 / Deal）——时间对得上的变化是最有说服力的证据。**再按主周期 {{主周期}}** 做日历周期对比：日 / 周 / 月各算市场变化率 M、竞品变化率 C，和自身变化率 S 对照，按 3.2 的表判定，**结论以主周期为准**。注意粒度：ABA 搜索量是周，类目市场规模一般是 30 天 / 月（周级别改用搜索量和竞品），竞品 BSR / 价格是日。西柚是第三方估算，日级别只作参考，结论以周 / 月为准。
4. 西柚拿不到（找不到工具、调用被拒、无额度）：不能跳过。先用浏览器、网页搜索补市场和竞品数据（标明来源，可信度最高"中"）；仍然补不到时，市场列填"缺数据"，判定填"无法判定"，外部因素一律标"未验证"、可信度不高于"低"，并写出要问用户的具体问题。不能因为没有外部数据就把原因归到内部。
5. 工具不限：除了西柚，还可以用浏览器看亚马逊前台搜索结果、竞品页面的价格 / Deal / 评论 / 新品，用网页搜索查季节、节日、平台活动、行业新闻。唯一不做的是写操作。

输出
把完整结果写到 {{数据目录}}/rootcause_external.md（写不进去就停下，回复第一行写明哪个路径写不进去，不要改写到其他目录）：
- 第①层结论一句话（市场降 + 竞品降 + 自己降 / 市场稳 + 竞品稳或涨 + 自己降 / 叠加 / 跑赢 / 无法判定）
- 市场对照表：周期 | 市场变化（指标 + 数值） | 竞品变化 | 自己 ASIN 变化 | 判定（第一行是"起点前后"，主周期那一行标 ★）
- 外部因素逐项：因素 | 数据来源 | 有无变化（数值 + 日期） | 影响指标
- 主因：每行 `[第①层] 原因 — 证据（数据+来源）— 影响指标 — 可信度（高/中/低）`，最多 5 条
- 缺失数据及原因
- 需要问用户的问题（写成能直接问的句子）

最后只回复（不要贴明细数据）：
1. 第①层结论一句话
2. 市场对照表（起点前后 + 日 / 周 / 月 共 4 行，主周期标 ★）
3. 主因列表（最多 5 行）
4. 缺失数据（一行一项）
5. 需要问用户的问题
6. 实际用到的核心词和竞品 ASIN（主代理和用户确认后写回记忆）
```

## 内部子代理 Prompt 模板（第④层 关键词权重 + 第⑤层 相对竞争力）

```
你的任务：找出一个亚马逊 ASIN 销量下滑在链接自身的原因：关键词权重（诊断框架第④层）和相对竞争力（第⑤层），以及库存、Buy Box、变体等 Listing 因素。只做归因，不给优化建议，不执行任何修改。

参数
- 用户原话：{{用户原话}}
- ASIN：{{ASIN}}（父体 {{父体ASIN}}），站点：{{站点}}，截止日期：{{截止日期}}
- 数据目录：{{数据目录}}（daily.csv、campaigns_daily.csv、variant_ads.csv、st_curr.csv、st_prev.csv、README.txt）
- 前面各层的结论：{{前序结论}}
- 用户已确认的情况：{{用户已确认的情况}}
- 核心词：{{核心词}}
- 竞品 ASIN：{{竞品ASIN}}

做法
1. 先读 {{skill目录}}/references/diagnosis-framework.md 的"④ 关键词权重""⑤ 相对竞争力"，再读 {{skill目录}}/references/step3-root-cause.md 的 3.3、3.4、3.5、3.6。按第②层的结论决定重点：流量降 → 先查④；转化降 → 先查⑤；双降 → 两个都查，⑤优先。
2. 先用数据目录里的文件，用 python 读 CSV 做统计，不要把整份文件读进上下文：
   - daily.csv 的 price / rating / inventory：价格、评分、库存有没有变化，变化日期
   - st_curr.csv / st_prev.csv：核心词的点击、订单、订单密度（订单 ÷ 点击）本期 vs 上期；核心词和泛词的花费占比
   - variant_ads.csv：其他变体的花费是否在变
3. 文件里没有的，再查 MCP（工具是延迟加载的，先用 ToolSearch 加载，用 select: 一次性加载要用的）：
   - 西柚：get_asin_keyword_rank_trends（核心词排名）、get_asin_keyword_count_trends（Top 10 / Top 20 词数）、get_asin_keyword_traffic_trends / get_asin_keywords（覆盖和流量占比）、get_asin_info_change_trends（自己和竞品的价格 / 主图 / 标题 / 评分变化）、get_asin_info（评分、评论数）、get_asin_variations（变体）。每次调用都填 user_task = 上面的"用户原话"（逐字），intent_summary = 这次调用要查什么、用来判断哪个因素。列表类工具 page_size ≤ 10；不要调用单次几百 credits 的报告类工具（如 generate_category_insight_resource）。
   - 领星（mcp__<ID>__help / search / action）：只调用 toolType=read 的工具；每个 toolId 先 search 看清字段再 action，不要猜参数。可查 FBA 库存、评论、退货、促销。
   拿不到就记为缺失，不要猜。
4. 第⑤层每一项都要**自己和竞品对比**：竞品降价、加 Coupon、Review 增长、升级页面或产品，都算自己的相对竞争力下降。
5. 工具不限：还可以用浏览器看亚马逊前台自己和竞品的 Listing、价格、Coupon、评论、Buy Box、配送时效，用网页搜索查质量问题或差评舆情等。唯一不做的是写操作（创建/修改/否定/调价/改预算/开关活动/改 Listing），发现该改的只写成原因和证据。广告操作由主代理看，你不用查。

输出
把完整结果写到 {{数据目录}}/rootcause_internal.md（写不进去就停下，回复第一行写明哪个路径写不进去，不要改写到其他目录）：
- 第④层结论一句话（排名 / 词数 / 覆盖有没有掉，原因属于：关键词转化下降 / 广告结构偏移 / 相对竞争力下降）
- 第⑤层结论一句话（价格 / 信任 / 页面 / 产品哪一项输给了竞品）
- 逐项检查表：因素 | 数据来源 | 自己（数值 + 日期） | 竞品 | 影响指标
- 主因：每行 `[第④层/第⑤层/Listing] 原因 — 证据（数据+来源）— 影响指标 — 可信度（高/中/低）`，最多 5 条
- 缺失数据及原因
- 需要问用户的问题（写成能直接问的句子）

最后只回复（不要贴明细数据）：
1. 第④层、第⑤层结论各一句
2. 主因列表（最多 5 行）
3. 缺失数据（一行一项）
4. 需要问用户的问题
5. 实际用到的核心词（主代理和用户确认后写回记忆）
```

## 子代理返回后（主代理做）

1. **外部回来后**才写 ②③ 结论、派内部；**内部回来后**才做第⑥层。子代理回报的结果文件不在数据目录里时，先移到数据目录。某个子代理失败或超时：先看它有没有写出结果文件；没有就重派一次；还失败，这一层标"未完成"，报告里写明，不要自己补编结论。
2. **把六层结论排好**：①（外部）、②③（第3步）、④⑤（内部）、⑥（主代理），每层一句，交给第7步归类。两边证据冲突时（如内部说库存正常、外部说断货），回到数据文件核对，以数据为准。
3. **统一问用户**：两个子代理、第⑥层和第6步关键词机会"需要问用户的问题"合并去重，一次问完。用户的回答会改变结论时，改完再进第7步。
4. **市场对照表**直接用于报告的第①层；外部子代理标了"无法判定"的，原样保留。
